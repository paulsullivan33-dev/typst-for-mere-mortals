# Writing criteria for this guide

Every "for Mere Mortals" guide is written to the same nine-point
standard, so a reader who trusts one can trust the rest. Here it
is, with the verification notes for this particular guide below.

1. **Fix it first.** Reader outcomes lead, not action items: each
   chapter opens by naming the outcome it delivers, shows a check
   the reader can run to confirm they got it, and a reasonable
   reader finishes able to state what was done, what it means,
   and what to try next.
2. **Plain language.** Short sentences, everyday vocabulary,
   technical terms defined on first use. No slang, and no
   idioms that only make sense in one country — the reader may
   be translating as they go.
3. **No dead ends.** A guide never tells the reader to do
   something it cannot show them how to verify. Every claim a
   reader relies on — an install, a command, an output — is
   something this guide demonstrates or clearly labels
   documented-only below.
4. **Live-verified where it matters.** Procedures are run for
   real in the guide's lab wherever the build machine allows it,
   and the transcripts kept in the repository are the evidence.
   What could not be run is listed honestly below, never
   presented as if it had been.
5. **General audiences.** Nothing in this guide — examples,
   fixtures, names, addresses — is modelled on any particular
   reader or author's real life, network, or organisations.
   The lab's society, its members and its money are invented.
6. **Standalone.** A reader needs this guide, its lab, and
   nothing else. Where another guide would genuinely help, it
   is pointed to once, by name, and the chapter still completes
   without it.
7. **Honest about limits.** Chapter 14 names what the tool
   cannot do: it cannot make a muddled document good, its HTML
   export is experimental, fonts belong to the machine and not
   the document, whole territories still belong to LaTeX, and
   the software is young enough that commands deprecate between
   versions — one did, during this lab.
8. **The ethics rule is in the text, early.** A `.typ` file is
   a program, and chapter 2 says plainly not to compile
   documents from strangers as casually as you would open a
   picture — the compiler reads data files inside its project
   folder by design. The other half of the rule is the good
   news, stated before any procedure depends on it: everything
   in this guide runs locally, and your documents and data never
   leave your machine.
9. **Builds clean.** The site builds with MkDocs in strict mode
   with no warnings, and a fresh reader following the chapters
   in order reaches the stated outcome of each.

## Verification notes for this guide

The build machine is a 2-CPU, 7.7 GB Ubuntu sandbox, shared with
other work while the lab ran. Typst **0.15.1** (build 9dfd3a08)
was installed from the official release archive
`typst-x86_64-unknown-linux-musl.tar.xz` (17,462,992 bytes,
SHA-256 a6d077d0a95eed5a2eba715b2dae06be954f624ccbf85758a03f389ded33118c)
and run unmodified. All transcripts live in `typst-lab/`
(t00–t09), together with the lab's `.typ` sources, its CSV and
JSON fixtures, and the chart script.

Run for real, with transcripts as evidence:

- Download, checksum, version and the full `--help` listing
  (t00, t01).
- `typst fonts`: 262 font families on this machine, including
  the embedded Libertinus Serif and New Computer Modern, and
  Lato — the heading font the styling chapter then uses (t02).
- A three-page society report compiled to PDF: `pdfinfo`
  reports 3 A4 pages, and `pdftotext` shows the generated
  contents with correct page numbers, the in-text reference
  resolved to "Figure 1", the figure caption, and the rents
  table's values. The chart inside it was generated by a Python
  script from five numbers summing to 635, matching the total
  the prose states (t03).
- The data rung: a stock report generated from `inventory.csv`
  and `inventory.json`. Typst rendered 165 items and a
  replacement value of £695.51; awk and Python each recomputed
  `items=165 value=695.51` from the same CSV — three programs,
  one answer, to the digit. `typst eval` (and the deprecated
  `typst query`, whose warning is kept) extracted the computed
  total back out of the document by label: `["695.51"]` (t04).
- Styling, measured two ways: the same page compiled plain and
  with set/show rules (Lato, 20pt, green `#1a5c2e`, underlined).
  The colour string appears 0 times in the plain SVG export and
  17 times in the styled one; counting pixels of exactly that
  green in the 100-ppi PNG renders gives 0 of 966,763 plain and
  655 styled (t05).
- Errors, verbatim: an unknown variable (location, caret span
  and the subtraction hint), and an unclosed parenthesis
  producing a six-error cascade headed by "unclosed delimiter"
  (t06). A multi-page SVG export refused without a `{p}` page
  template, then succeeding with one: 3 PNGs (595 × 842 at
  72 ppi) and 3 SVGs with file facts recorded (t07).
- One Typst Universe package, numbly 0.1.0, used for a heading
  numbering format the built-in patterns cannot express; the
  output shows A. / 1) / B. numbering as specified. Typst's own
  download of the package failed through this sandbox's proxy
  (TLS error, kept verbatim); the identical tarball was fetched
  with curl (SHA-256 e349be2ff133f3b7154f97462e73862ee31de613e506ef06964069a35756ff12),
  unpacked into the local package cache, and the compile then
  succeeded without the network (t08).
- Recipes verified by compiling: a letter with a repeating page
  header (the header text extracts above the date), and a
  two-column newsletter with a masthead spanning both columns —
  after two verbatim diagnostic failures that located the
  correct `place` form (t09).
- A defect found and fixed during the lab: Typst prints
  rounded money as £107.5, not £107.50. The guide's `money`
  function (chapter 7) fixes the presentation; t04's rerun
  shows the corrected column (£51.00, £99.96, £107.50, ...).

Documented only — described from the project's documentation,
not run, and the text does not claim otherwise:

- The hosted editor at typst.app and collaboration.
- HTML export, which the project labels experimental.
- Fonts installed on a reader's real machine, and every
  platform's install route other than the Linux release binary
  (package managers, cargo).
- Print production: printing the PDFs, colour on paper, PDF/X
  and print-shop workflows.
- The neighbour tools of chapter 13 (LaTeX, Pandoc, LibreOffice
  behaviour, the web generators) — characterised, not run or
  benchmarked here.
- `typst watch` and `typst init` were not needed by the lab's
  targets and are described from the help text and docs;
  templates in particular would have needed the package
  registry over the network.
- What the pages *look like*. The lab had no eyes: every claim
  is a measurement (pages, text, pixels, totals). Beauty is the
  reader's judgement, and the guide never grades it.

Fixtures are this guide's own and deliberately generic: the
Bramble Lane Allotment Society, its forty-one plots, its shed
inventory and its £750 budget are invented, as are Mrs Ellison
and J. Hartley. No real organisation, person or accounts appear
anywhere in the lab.
